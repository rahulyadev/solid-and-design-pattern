This repository is public. Public visibility is not the same as permission to reuse, redistribute, or create derivative works.

## License decision point

Do not add a license automatically.

Rahul must explicitly choose one of:

1. Leave the repository without a license.
2. Apply one license to the entire repository.
3. License software code and educational notes separately.

Before adding a license, Codex must explain permissions, attribution, redistribution, commercial use, patent terms when relevant, warranty and liability, suitability for code versus prose and diagrams, third-party material, and contributor implications.

Until a license is selected, do not add `LICENSE`, describe the repository as open source, or assume that public visibility grants general reuse rights.

## Original-writing rule

Write explanations, diagrams, examples, exercises, labs, and projects in original language.

Codex must paraphrase sources, cite important claims, use only short quotations when exact wording is necessary, mark quotations clearly, preserve required attribution for legitimately reused material, and avoid recreating a book, course, article, documentation chapter, paid exercise set, or proprietary training resource.

A citation does not make extensive copying acceptable.

## Design books and diagrams

The Gang of Four book, refactoring books, enterprise-pattern books, and other copyrighted works may be cited and summarized. Do not reproduce their diagrams, pattern templates, long definitions, or examples substantially. Create original Python examples and original diagrams that reflect the verified idea.

## External code

Before reusing code:

1. Identify its license.
2. Confirm the intended use is permitted.
3. Preserve required notices.
4. Prefer a small original Python example.
5. Avoid code whose license is absent, unclear, or incompatible.

Do not copy employer systems, private repositories, paid courses, interview take-homes, or confidential documents.

## Privacy and confidentiality

Do not commit credentials, secrets, tokens, private keys, personal or medical information, employer-confidential code or architecture, customer or supplier data, proprietary datasets, production incidents, private screenshots, or unrelated conversation transcripts.

Use synthetic names, records, events, providers, services, logs, paths, and credentials.

## License-change procedure

A license change is complete only when Rahul approves the option and exact text, covered paths are explicit, third-party material is audited, README guidance is consistent, required notices are present, and the change is reviewed before publication.
